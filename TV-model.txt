5. Firmware
- Those DCF tokens are not derived from the retail model, article number, serial, or MAC. CRC16/CRC32/MD5/SHA-1 over the Medion profile strings and over D65U546A / 2199818 / SN 8368599 900143 / 0.51.52.3 do not produce `772e` or `0009df`. S3 returns AccessDenied for both `0009df/772e.dcf` and a nonsense key, so a guessed path cannot be checked. `17MB230` is shared by many brands and does not select a file. `orion.portaltv.tv` takes country/brand/device/swversion as a query for the app list, not as the firmware object path.
- OTA client is the same on this chassis as on the Medion image. In `mb230_swprofile.bin` (apdat, file offset about `0xcf444db`) the Medion profile stores descriptor `772e.dcf`, id `0009df`, host fragments `s3-eu-w` + `*-1.amazonaws.com/vstlupdate`, key `SERVER_HTTP_SECURE_TYPE`, chassis `17MB230`. The bucket `vstlupdate` exists in `eu-west-1` (S3 answers 403 with `x-amz-bucket-region: eu-west-1` for `/`, `772e.dcf`, `0009df/772e.dcf`, and `17MB230/772e.dcf`). Listing is not public, and that DCF id is the Medion project's, not Telefunken 0.51.52.3. Vestel Security Target: OTA is TLS 1.2/1.3, the image is symmetric-encrypted, and the TV checks the signature before decrypt. A captured OTA blob is not a plaintext Kylo image. `orion.portaltv.tv` is the app portal, not this update bucket.
- Exact Telefunken build 0.51.52.3: still no public file. Telefunken has no download portal.
