# Amp mute/balance as ordered owner jobs — 2026-11-07

Scope: close the last HIGH review item by moving the AD82587 mute GPIO/STBC
level and balance register writes off the host loop. Host tests plus ARM build;
no TV access and no audible acceptance.

## Before

`audio_amp` ran `oa_amp_vendor_level()` (STBC/GPIO) and
`oa_amp_i2c_write(4/5)` directly in `iface_set_mute`/`iface_set_balance`, only
guarded by `-EBUSY` while an Init was submitted. The blocking writes therefore
ran on the host loop, and the owner worker was the only place guaranteed to
serialize them with Init.

## Owner API

`oa_amp_completion` now carries a job kind and operand:

```c
enum { OA_AMP_JOB_INIT, OA_AMP_JOB_MUTE, OA_AMP_JOB_BALANCE };
struct { uint64_t ticket; int kind; int native_result; int value;
         oa_amp_init_state state; };
```

New entry points:

```c
int oa_amp_owner_submit_mute(oa_amp_owner *, int on, uint64_t *ticket);
int oa_amp_owner_submit_balance(oa_amp_owner *, int balance, uint64_t *ticket);
```

The existing one-pending-request-OR-untaken-result contract is unchanged:
`-EBUSY` while a job is pending or its result is untaken, `-ESHUTDOWN` after
quiesce, `-EOVERFLOW` at ticket exhaustion. Because there is one ordered slot,
mute/balance cannot overtake a pending Init; `amp-mute` returns `-EBUSY` while
Init is in flight (the same visible behavior as before). The profile/name copy
for an Init still happens only when the queue is free, so a rejected submit
cannot mutate a pending job's input.

The worker dispatch:

- **Init**: `oa_amp_init()` as before, result 1/0, full state copied.
- **Mute**: `io.gpio(context,1)` selects the board mute record, then
  `io.level(pin, on ? level_on : level_off)`; 0 success, `-EIO` on a vendor
  boolean failure, `-ENOTSUP` without a record. This is the same mapping
  `oa_amp_init` uses, not a raw 0/1 bypass.
- **Balance**: `oa_ad82587_balance_regs()` then `io.write(reg4)` and, only on
  success, `io.write(reg5)`; 0 success, `-EIO` on failure.

No callback is invoked by the submit functions; all GPIO/STBC/I2C calls run on
the owner worker.

## Module result handling

`iface_set_mute`/`iface_set_balance` now submit a typed job and return after
submission (`amp-mute`/`amp-balance` are asynchronous like `amp-init`).
`poll_result` dispatches on the completion kind:

- Init completion replaces the retained `c->result`, sets `have_result` and the
  trailing-mute cache;
- mute/balance completions update only their own cache and **never** overwrite
  `c->result`, `have_result` or the Init ticket;
- failed mute/balance jobs leave the cached value unchanged and log the error.

A pending job still makes the next command `-EBUSY`, so a mute cannot be
accepted while Init is running or its result is untaken. `amp-state` reports
`busy`, the Init result, and the applied mute/balance values; the CLI has no
blocking hardware write path.

## Tests

`check-amp-owner-jobs` (`tests/amp_owner_jobs.c`):

- Init is held in the fake prelude; `submit_mute`/`submit_balance` must return
  `-EBUSY`; after release the Init completes.
- Mute runs on the worker with record pin 208 and level 1/0; failed level
  returns `-EIO`.
- Balance 25 writes reg4=0 then reg5=64; 50 writes 0/0; a reg5 failure returns
  `-EIO` after the visible reg4 write.
- A completed-but-untaken result also returns `-EBUSY`; invalid on/balance and
  NULL tickets reject.
- Negative checks: allowing a second submission while Init is pending makes the
  ordering assertion fail.

`check-audio-amp-jobs` (`tests/audio_amp_jobs.c`) includes the module source:

- A pending Init blocks `iface_set_mute`/`iface_set_balance`.
- After Init, a mute completion sets `mute=0` while `have_result`, the Init
  ticket and `native_result` remain unchanged.
- Balance 25 updates only balance; failed mute/balance leave caches unchanged;
  invalid values return `-EINVAL`.
- Negative check: making `poll_result` copy every completion over the Init
  result fails the mute/state assertions.
- Every fake GPIO/I2C callback asserts it is not on the main thread, so a
  regression back to loop-side writes trips the test.

```text
ok amp owner jobs: mute is ordered after Init and runs on the worker
ok amp owner jobs: failed mute returns -EIO on the worker
ok amp owner jobs: balance writes reg4 then reg5 on the worker
ok amp owner jobs: failed balance leaves the partial write visible and reports -EIO
ok amp owner jobs: untaken result keeps the single-slot backpressure
all amp owner job tests passed

ok audio_amp jobs: pending Init blocks mute/balance; Init state is retained
ok audio_amp jobs: mute result does not overwrite the Init result
ok audio_amp jobs: balance result keeps mute and Init state
ok audio_amp jobs: failed mute/balance report no cache success
all audio_amp job tests passed
```

Existing `check-amp-owner`, `check-audio-amp`, `check-amp-vendor` and
`check-audio-amp-module` also pass.

## Limits

- No hardware or audible run; mute/balance acceptance still requires the TV,
  an enabled module, and owner listening.
- `amp-mute`/`amp-balance` now report submission success; a later transport
  failure is visible in `amp-state`/logs, not in the command reply.
- A job is not queued behind a pending Init (the owner has one slot); the
  caller gets `-EBUSY` and must retry. This matches the previous backpressure.
- Balance failure can leave reg4 updated and reg5 stale, as the vendor order
  does; there is no rollback.
