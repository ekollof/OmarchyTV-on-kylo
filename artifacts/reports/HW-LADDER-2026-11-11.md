## Procedure (each stage)

1. `oa-wdtfeed --node /proc/nvtstbcipc --interval 3 --timeout 10` started and
   logged two beats before stock was touched.
2. The appmgr was paused with `SIGSTOP` and stock `run_aurora.sh`/`aurora.elf`
   were stopped. The feeder kept beating.
3. `openaurora --modules <stage>/modules --config <stage>/hwN.conf` started
   with the stage autoload list.
4. The ready receipt (`/tmp/openaurora.ready`) and the stage states were read.
5. `oa-client ... quit` stopped/unloaded the modules; the process exited.
6. The feeder stop file was written, its beats stopped, and a clean `reboot`
   restored stock.

### hw4 — NIM-DTV

```text
tuner hw: rc=0 failed_step=5 nim=1 hal=1 tuner=1 seq=1 seq_rc=0 lnb=1
          ir_code=21 ir_write=0 errno=1
```

All five modules loaded and started; the ready receipt was written. `failed_step
5` is `OA_NIM_DTV_STEP_IR21` (IIC code 0x15). The failing call was the
**read**, not the write: `ir_write=0` is set by `hw_ir_read`; the separate
`ir_write=1` value marks a write failure. The recovered task calls
`DEV_IIC_Read/Write(0, 0, 0x80, 1, 0x15, 1, &byte)`; the kernel logged
`ki2c: [i2c-0] Dev NACK`, and NDAL collapsed the NACK to failure with
`errno=1` (EPERM). This is the vendor-tolerated NIM-DTV branch: every IIC
failure jumps to the finish path `0x00860252`, sets the active module to
`0xff` and signals; `DEV_NIM_DTV_WaitInitComplete` only waits for that signal.
It is **not** a clean NIM IR/EEPROM pass, but it is not a hw4 regression.

### hw4 IR21 cause and RF/lock rerun

A second hw4 run used `mod_tuner.so` `49defdfd…` with `errno=0` set before
each IR read/write so the recorded errno is attributable to that call. Result:

```text
tuner hw: rc=0 failed_step=5 nim=1 hal=1 tuner=1 seq=1 seq_rc=0 lnb=1
          ir_code=21 ir_write=0 errno=1
ki2c: [i2c-0] Dev NACK
```

`errno=1` is therefore the NDAL/kernel NACK result, not a stale value. The
read of IIC code 0x15 on bus 0/slave 0x80 NACKs; the vendor task treats that
as a tolerated IR/EEPROM failure and continues to a started tuner service.

The RF/lock check used the tuner control path:

```text
tuner-state: network 0 state 0 progress 0 lock 0 services 0 selected 0
             error 0 strength 0 quality 0 ber 0.00 snr 0.00 unc unknown
tuner-scan 1: ok
tuner-state: network 1 state 1 progress 25 lock 0 services 3 ...
tuner-state: network 1 state 1 progress 50 lock 0 services 6 ...
tuner-cancel: ok
tuner-state: network 1 state 3 progress 50 lock 0 ...
```

The service count advances, but it is the module's fixture scan. There was
**no RF source** connected, so `lock 0`, `strength 0`, `quality 0`, `ber 0`,
`snr 0` are the expected no-signal values, not a tuner defect. A real
RF/lock acceptance needs an antenna or signal generator on the tuner input;
that is an owner/environment prerequisite, not something the current bench
can supply.

## Limits

- This is **not** a cold boot. The vendor kernel/PreInit had already
  initialized the hardware; the appmgr was paused; the boot hook and
  watchdog-ownership handoff were not exercised.
- No display, UI, scanout or framebuffer effect is tested. The panel was
  powered and set to 100%, but visible brightness/timing and the panel
  power-off sequence were not measured.
- hw2 proves the MCLK command path, not audible output or a mixer/amp effect.
- hw3 proves the SPI backend open, not any SPI transaction.
- hw4 is a sequence-completion result with the vendor-tolerated IR21 read NACK
  (`ki2c: [i2c-0] Dev NACK`, errno 1); it does not prove the NIM IR/EEPROM,
  tuner detection, RF lock, demod or picture. The `tuner-scan 1` progress is
  the module's fixture scan; `lock 0`/`strength 0` reflect the absence of an RF
  source.
- A real RF/lock acceptance requires an antenna or signal generator connected
  to the tuner input. That is the next owner/environment prerequisite; without
  it the scan cannot prove lock.
- One run per stage; no repeatability, stress or power-cycle matrix.
- The TV was left in stock operation. No firmware, `/conf` flag, boot hook or
  persistent module change was made.
