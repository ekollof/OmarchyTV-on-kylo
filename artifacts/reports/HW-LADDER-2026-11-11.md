## Procedure (each stage)

1. `oa-wdtfeed --node /proc/nvtstbcipc --interval 3 --timeout 10` started and
   logged two beats before stock was touched.
2. The appmgr was paused with `SIGSTOP` and stock `run_aurora.sh`/`aurora.elf`
   were stopped. The feeder kept beating.
3. `openaurora --modules <stage>/modules --config <stage>/hwN.conf` started
   with the stage autoload list.
4. The ready receipt (`/tmp/openaurora.ready`) and the stage states were read.
5. `oa-client ... quit` stopped/unloaded the modules; the process exited.
6. The feeder stop file was written, its beats stopped, and a clean `reboot`
   restored stock.

### hw3 — SPI

```text

```

`/conf/spi.bin` does not exist on this set; the module used the recovered
fallback `/dev/ntkspi` (char 245:0). The service started and the ready receipt
was written. No SPI read, write, erase or flash command was issued.

### hw4 — NIM-DTV

```text
tuner hw: rc=0 failed_step=5 nim=1 hal=1 tuner=1 seq=1 seq_rc=0 lnb=1
          ir_code=21 ir_write=0 errno=1
```

All five modules loaded and started; the ready receipt was written. `failed_step
5` is `OA_NIM_DTV_STEP_IR21` (IIC code 0x15). The IR21 write returned failure
(`ir_write=0`, `errno=1`). This is the vendor-tolerated NIM-DTV failure branch:
the task still marks init done and `DEV_NIM_DTV_WaitInitComplete` only waits
for that signal. It is **not** a clean tuner hardware pass: the IIC code 0x15
read/write did not succeed.

## What this establishes

- The real ARM ladder completed all five documented stages on the TV, one
  module owner at a time, with the ready receipt only after the autoloaded
  modules started.
- `plat` completed the recovered `PLAT_DRV_INI_Init` HAL sequence on hardware,
  including DRM mode setting and `NDAL_VideoExt_OpenDevice(0,10)`.
- Panel power/backlight (100%), the I2S MCLK request, the SPI device open and
  the NIM-DTV task all executed through the shipped vendor libraries.
- The external feeder kept the set alive while stock Aurora was stopped, and a
  clean reboot restored stock after each stage.

## Limits

- This is **not** a cold boot. The vendor kernel/PreInit had already
  initialized the hardware; the appmgr was paused; the boot hook and
  watchdog-ownership handoff were not exercised.
- No display, UI, scanout or framebuffer effect is tested. The panel was
  powered and set to 100%, but visible brightness/timing and the panel
  power-off sequence were not measured.
- hw2 proves the MCLK command path, not audible output or a mixer/amp effect.
- hw3 proves the SPI backend open, not any SPI transaction.
- hw4 is a sequence-completion result with the vendor-tolerated IR21 failure;
  it does not prove tuner detection, RF lock, demod or picture.
- One run per stage; no repeatability, stress or power-cycle matrix.
- The TV was left in stock operation. No firmware, `/conf` flag, boot hook or
  persistent module change was made.
