# Review of the row renderer and SVG image work — 2026-11-04

Reviewed28ef959..b50e3f0: row setters, all renderItems case families,
LauncherHelper image mapping, selection-image orchestration, SVGImage
create/destroy and their tests. Full replacement/rendering acceptance remains
open. This review fixes implementation and coverage defects; it does not start
the pending imageCreate subsystem or a persistent TV replacement.

## Corrections

**Image resource overflow.** The C create helper allocated16 bytes. Firmware
reserves32 bytes (stack+24..44, in hex); DynamicImageSupplier::getImageResource
copies words through offset1c. Read-only ARM/decompile evidence is in
analysis/ui-review-2026-11-04/source.txt and supplier-source.txt. The old tests
wrote only16 bytes and compared pointer identity, hiding the overrun. The
helper now provides32 bytes aligned to max_align_t. Both unit/reference
suppliers write all32 distinct bytes and image_create verifies them. Required
callback validation runs before effects. Resource/rectangle lifetime and actual
backing object storage at surface offset9c are explicit; the host test uses a
real object and uintptr_t rather than fabricated/truncated host addresses.

**Progress arithmetic UB.** renderItems duplicated the percentage calculation
with signed value-lo and hi-lo subtraction, plus unchecked INT32_MIN/-1
division. UBSan halted on INT32_MAX-INT32_MIN in a new regression (percent-before
log). Rendering and the setter now share checked unsigned wrapping arithmetic,
bit-preserving signed interpretation and the explicit quotient overflow case.

**Incorrect divide-zero claim.** Source instructions at12856fa select the
signed limit, then unconditionally branch to1285d84, which calls raise(8)
regardless of the numerator. The prior “nonzero/zero returns INT_MAX/MIN”
claim was wrong, and its stub made the tests agree with the wrong assumption.
All zero ranges now return EDOM, with unchanged percentage output. The progress
setter returns before widget effects/stores; rendering retains earlier text
work and propagates EDOM before the percentage update. The standalone percentage
API now returns errno and writes through an output pointer. This is an explicit
error-handling deviation from firmware's crash path, not a claim of fault parity.
No native zero-divide or signal path was executed on the TV or under QEMU.

Both reference groups now copy/execute the actual660-byte divide fragment at
1285478, CRC32 a99eabd1, including computed branches, for nonzero divisors.
The48 previously synthetic zero-range setter cases were removed, leaving276
real native comparisons. Renderer edge cases include both signed subtraction
overflows, negative divisors, wrapped multiplication and INT32_MIN/-1.

**Checked-byte narrowing.** The checkbox renderer normalized row byte2e44 to
0/1; firmware forwards the loaded byte. The implementation now preserves it,
and all256 byte values are tested in both created states (512 added cases).

**Paired-child coverage.** Image1/image2 and text3/text4 previously shared one
created flag. Added independent second-child overrides and40 comparisons for
mixed states across launcher/image/progress/text consumers. The earlier mixed
state claims were stronger than the actual fixture coverage. No additional
production mismatch appeared in those new cases.
