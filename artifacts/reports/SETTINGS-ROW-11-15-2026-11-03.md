# Settings-row renderItems types 0x11..0x15 (text-entry family) — 2026-11-03

`common/settings_row_render.c` now covers the remaining text-entry variants
through the same parameterised body as 0xd/0xe/0xf/0x10. All five look up
**"selectionbox"** (through their own literals: `0xd55498` for
0x11/0x12/0x13/0x15 and `0xd5574c` for 0x14), drive `row+0x18d8`, write
`row[0x2ec0]/[0x2ebc]/[0x2ec8]/[0x2ec4]` into name slots **1/0/3/2**, create
with the (0, 0xc, 0xd) triplet from `0xd5549c`/`0xd55750`, and apply EASIRect
math + `setWindowRect` when created. They differ only in the trailing setters
and the created text source:

| type | entry mode | max chars | created source |
|---|---:|---:|---|
| 0x11 | 3 | 10 | `setText` row UString `0x2e0c` |
| 0x12 | 4 | 5 | `setText` row UString `0x2e14` |
| 0x13 | 5 | **none** | `setText` row UString `0x2e1c` |
| 0x14 | 2 | 4 | `setText` row UString `0x2e24` |
| 0x15 | 9 | 15 | `setNumericContents(row[0x2e00])` |

All except 0x13 finish with `setMaxNoOfChars` + `setCursorMoveAutomatic(1)`.
0x13 sets only the entry mode and returns — no max, no cursor call (the
`0xd5545c` `b.w` return). **394384** native/C comparisons pass with exact call
order/args, rect words, text bytes and row state, plus strict host, focused
ASan/UBSan, ARM/qemu, all prior groups and a focused real-TV CPU run (exit 0).

## Source and recovered behavior

Aurora MD5 `64c252340d3af6c5d66072611b7bad7a`. Read-only objdump/ELF. Jump
table entries: 0x11 -> `0xd5522c`, 0x12 -> `0xd552f8`, 0x13 -> `0xd553c2`,
0x14 -> `0xd554a0`, 0x15 -> `0xd55148`.

Shared shape (children and create): names 0x2ec0 (slot 1), 0x2ebc (slot 0),
0x2ec8 (slot 3), 0x2ec4 (slot 2); `create(0, 12, 13, UString(empty),
rect+8, row)`; created path re-uses the `0xd552e6`/`0xd553b0`/`0xd55484`/
`0xd55558`/`0xd5521e` `setWindowRect` blocks.

The tails differ:

- **0x11** rejoins `0xd54f9c` with r1=3: `setEntryMode(3)`, then `0xd54fa2`
  max 10, then cursor auto.
- **0x12** rejoins `0xd55100` with r1=4: `setEntryMode(4)`, then `0xd55106`
  max 5, cursor auto.
- **0x13** rejoins `0xd55454` with r1=5 and **returns at `0xd5545c`** after
  `setEntryMode(5)`.
- **0x14** rejoins `0xd54eca` with r1=2: `setEntryMode(2)`, then max 4,
  cursor auto.
- **0x15** rejoins `0xd551da` with r1=9: `setEntryMode(9)`, max 15, cursor
  auto; its created path calls `setNumericContents(row[0x2e00])`.

The five `create` sites pass 12/13 (decimal), identical to 0xd's 0xc/0xd.

As part of this slice the ops surface dropped `row_value_text` and now routes
**every** row-side UString through the generic `row_ustring(row, offset)`
(0x2e04, 0x2e0c, 0x2e14, 0x2e1c, 0x2e24, 0x2e2c, 0x2e34), so there is one
code path for UString reads instead of two.
