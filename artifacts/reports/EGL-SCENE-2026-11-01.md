# Owned offscreen Mali scene rendering — 2026-11-01

Status: firmware-understood EGL pbuffer owner and scene renderer implemented
and executed on the actual Mali-G51. No recording/fake screen or host GPU was
used for runtime evidence. These helpers do not access native windows, swap,
fbdev or platform HAL. Production display/module integration and direct EGL
presentation remain open; this is not independent startup or visible parity.

## Implementation

common/scene_gles.c and its header own a display, pbuffer, unshared context,
texture and shader program. Creation retains partial state on failure for
explicit close/retry. Every call checks creating PID/thread; rendering also
checks that its context is current. Close retains unfinished EGL handles on
failure and releases the owner only after cleanup succeeds. It does not unbind
a different current context. This lower synchronous owner is **not** wired into
the host loop/module lifecycle yet; future adapters must retain code/library
dependencies until close succeeds. No worker cancellation/standby is claimed.

Input is tightly packed top-down straight RGBA. Vertex UVs invert v to account
for that CPU orientation, while retaining the recovered clip-space fan and
oa_fs_apply geometry. GL_LINEAR/CLAMP_TO_EDGE and progress-alpha/blend match
UI-SCENE-REVIEW. Readback is **bottom-up premultiplied RGBA**, not framebuffer
BGRA. An eventual fbdev consumer must reverse rows and convert channels; a
direct EGL surface must use its established native contract instead.

tools/display/egl-probe.c checks context/clear/readback/cleanup.
tools/display/egl-scene-probe.c checks small identity/orientation for all types,
independent keystone samples (green27/33, matching CPU golden values), fade,
undersized-input rejection, close/reopen and 1080p upload/render/readback timing.
Both diagnostics are explicit opt-in make targets, never run by make check.
Host and ARM builds retain C11 -Wall -Wextra -Werror -pedantic. Installed
Khronos headers are searched after the cross toolchain's standard headers.
ARM links the target libmali directly with /vendor/lib runtime lookup.
