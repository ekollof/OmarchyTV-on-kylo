# Host shutdown retry — 2026-11-01

Correction/follow-up: [DISPLAY-DSO](DISPLAY-DSO-2026-11-04.md) found that this
implementation could enter poll(-1) after the last timer disappeared, even
with a completed quiescence worker. Actual-host GDB evidence is preserved.
Shutdown now caps poll at20ms to guarantee another gate attempt without a new
event. The older nine groups below did not cover this no-notification case.

Review clarification: a quiescence veto always counts as potentially pending
future work, even with no queued post, timer or watch. Such a veto may wait
indefinitely. The no-work error below applies to retained non-quiescence holds;
the host does not detect a dead worker from queue emptiness. WORK-REVIEW records
the later nonblocking owner gates and retryable pending reload.

The quiescence gate could already refuse dlclose. `oa_host_run` left the loop
before cleanup, ignored stop/unload errors, and never dispatched the completion
post that would let a later retry succeed. This change keeps shutdown on the
loop thread.

After stop is requested, the host dispatches posts and due timers, then stops
and unloads in reverse slot order. A veto leaves the instance loaded. If the
gate queued a completion, that post is dispatched and stop/unload runs again
before the host waits. Otherwise the host waits on the self-pipe, a module
timer or a module fd watch. Host-owned watches, including the control socket,
do not by themselves count as module completion work. Load, start, reload,
suspend, resume and the sleep cycle refuse once shutdown has started. Stop and
unload remain available. `--force` is not used.

If every module unloads, `oa_host_run` returns 0. If a module is still loaded
and nothing queued, pending or watched can make progress, it logs the module
and returns -1. The DSO stays mapped. `main` then exits 1. A stuck gate with a
worker that has not posted yet waits; the host does not unload it to make
progress.

Nine real-DSO groups in `tests/quiesce.c` pass strict host, ASan/UBSan and
ARM/qemu against `artifacts/workbench/rootfs/root`. Three of them are new:
completion posted by the gate itself, completion posted by another thread while
the host is waiting, and a held service that must stay loaded. Control reply
and transport groups also pass on the strict host and under ASan/UBSan. The
ARM `make check-quiesce` recipe executes the binary directly and is not the
qemu result; the passing run is `qemu-arm-static -L` of
`build-tv-v3/tests/quiesce`.

not rebuilt. This core was not started on the TV, and `--check` was not repeated.
