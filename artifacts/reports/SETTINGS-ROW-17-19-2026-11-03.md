# Settings-row renderItems types 0x17..0x19 (progress-bar rows) — 2026-11-03

`common/settings_row_render.c` now covers the three progress-bar rows. With
these, **every switch case body 0..0x1a** in `renderItems` is implemented and
verified. The shared percentage math is
`100*(row[0x2dfc]-row[0x2df0])/(row[0x2df4]-row[0x2df0])`, 32-bit wrapping
with truncating signed division matching the shipped `__aeabi_idiv` call at
`0x1285478`. **886060** native/C comparisons pass with exact call order/args,
rect words, text bytes, ball ids, percentage and row state, plus strict host,
focused ASan/UBSan, ARM/qemu, all prior groups and a focused real-TV CPU run
(exit 0).

## Source and recovered behavior

Aurora MD5 `64c252340d3af6c5d66072611b7bad7a`. Read-only objdump/ELF. Jump
table entries: 0x17 -> `0xd55ce8`, 0x18 -> `0xd55f60`, 0x19 -> `0xd56162`.

| type | rectangle keys (in order) | children |
|---|---|---|
| 0x17 | `progressbar`, `text2` | `row+0x24e8` text box, `row+0x1570` bar |
| 0x18 | `progressbar`, `text2` | `row+0x24e8` text box, `row+0x1724` bar |
| 0x19 | `progressbar`, `image1`, `image2` | two images, `row+0x1724` bar |

**0x17** is the only one with an alexa dependency: the text box uses the
`0x1e8..0x1eb` names, gets `setFont(0x1e)` when the prologue alexa rect exists,
and always shows the formatted `row[0x2dfc]`. The bar's uncreated path reads
row byte `0x2e46`: zero writes **no names and no ball images**; non-zero with
alexa writes four `0x26a` names plus ball image 892 for states 1/0/3/2; non-zero
without alexa writes names 1=0x35, 0=0x38, 3=0x36, 2=0x37 and ball images
169/169/170/170 for states 1/0/3/2. Then `setFocus(0)`, create and
`setPercentage`. Created bars take rect math + `setWindowRect` + percentage.

**0x18** drops the alexa branch and the font call (fixed `0x1e8..` names). Its
bar names are 1=0x1bd, 0=0x1be, 3=0x1c0, 2=0x1bf; when row byte `0x2e46` is
set it applies the 169/169/170/170 ball images **and**
`setDoubleDirectionalBar(1)`.

**0x19** prepends the image1/image2 block: create from `row[0x2e4c]`/
`row[0x2e50]` when uncreated, or — when both are created — refresh with
`setWindowRect` on each plus **`setVisible(1)`**, which differs from type 0xb's
refresh (that one has no visibility call). It then runs the same bar tail as
0x18.

All three share the `0xd55e86` `setPercentage` rejoin and the same
`__aeabi_idiv` percentage computation.

## Verification and limits

**886060** native/C comparisons: **Pass A** 27 types × 16384 fourteen-key
presence masks × created; **Pass B** point/word/label/flag coverage with every
key present; **Pass C** type 0xb over both image-created states; **Pass D**
type 0xc over both textbox-created states; **Pass E** types 0x17..0x19 over
both `0x2e46` states; plus eight default-type cases — the exact predicted
total. Host units add both 0x17 alexa branches, the `0x2e46`-clear path, the
0x18 name/double-directional pair, the 0x19 image create/refresh-with-visible
and the percentage value. Strict full host/actual Unix IPC, focused
ASan/UBSan, fresh ARM/qemu units, every prior group and the focused TV CPU
test pass. Isolated build `build-tv-v3/settings-row-render`:

| executable | bytes | MD5 |
|---|---:|---|
| tests/settings_row_render | 221916 | 6f887a7fe7ece4dd590c84e87b9e887e |
| tests/tab_policy_firmware | 1168648 | 8c3f0e7a70091990cbc63513bd244367 |

New harness pieces: `set_ball_image`, `create_progressbar`, `set_percentage`
and `set_double_directional` callbacks; a silent `__aeabi_idiv` trampoline at
`0x1285478`; and the progress-bar child pages. Every callee of the three
ranges was audited before sweeping.

**Limit:** the division is exercised only with a fixed 10..90 range
(`hi != lo`). Division-by-zero behaviour of the vendor runtime is not
characterised, and the host C would trap on it, so that input is not swept.
The percentage is also only tested with positive operands.

The standalone TV test requires only GLIBC_2.4 and the correct ARM loader.
tools/tvssh.sh found the TV already awake, verified the no-reset flag/free
space, staged only the focused binary and checked size/hash in a separate
connection before execution. Test exit 0 passed, staging was removed and the
`/proc/*/exe` scan found no helper; `/conf/coredumpnoreset` remained present.
No vendor fragment, device API, screen/input/audio control, service restart,
network/settings/boot mutation or persistent deployment was run on the TV.

This closes the `renderItems` switch: cases 0..0x1a are all implemented.
