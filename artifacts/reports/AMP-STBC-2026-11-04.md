# Amplifier MCU GPIO transport boundary — 2026-11-04

Firmware decompilation/ARM inspection preceded `common/amp_stbc.c`. This is a
synchronous injected-request codec for physical mute208 -> MCU GPIO8, not a
native backend. It never opens a device, initializes NDAL, installs a global fd
or falls back to native I/O. No TV, MCU or fb1 operation occurred.

## Recovered path and ABI

New durable Ghidra project: artifacts/workbench/ghidra_ndal_ex, ndal_ex/libNDAL_EX.so,
MD5e6a465861d1869b8b138b3f299c89f87. Initial import/analyze created the project;
all subsequent runs use readOnly/noanalysis. ndal-transport.txt, ndal-common.txt
and device-literals/mapping.txt are under analysis/amp-stbc-2026-11-04.
Kernel evidence is from nondovi MD5fded7005651e37b8a1b5e8e89f73f4ff in the
same directory. No saved prototype was treated as an ABI guarantee.

1. NDAL_VideoExt_STBC_SetStbcGpio4db5a3b8 builds three controls, ID0f170f0f:
   one-byte device result, one-byte pin, one-byte command. GetStbcGpio4db5a458
   builds four controls, ID0f170f10: result, pin, output0, output1. All control
   sizes are1; list class0f170000 uses ioctlc0185648. ARM controls are20 bytes,
   pointers at+12; list24 bytes, controls pointer+20. The helper has ARM static
   assertions and zeroes reserved words, including the field modern headers
   call request_fd. It does not use a host-sized ioctl constant on ARM.
2. The getter has **three** arguments: pin and two uint32 output pointers. Its
   instructions retain r1/r2 and store each widened returned byte through them.
   Do not call it as a two-argument getter. This does not establish the cause
   of historical resets/crashes; no historical binary/core was examined here.
3. The relevant _send_v4l2_command is4db586b8. A second identically named local

   ndcommon_v4l2_ioctl4db66c70 uses a process-global fd and returns whether
   v4l2_ioctl returned!=-1, not the device-result byte.
4. kernel-callers.txt identifies EX_PLAT_VBI_ext_ctrls619a60 as the dispatcher
   despite that broad function name. At619d7c Get calls DRV_STBC_GetGpioState
   with the pin and two byte pointers, copies outputs to controls2/3 and its
   boolean to control0. Set calls DRV_STBC_SetGpioState at619dc4 and stores its
   boolean into control0. The getter branch returns1 even if the device boolean
   is0; ioctl success and MCU operation success are distinct.
5. DRV_STBC_GetGpioState534578 uses ipc_send_and_wait_reply(1,3f,pin,0,0,3f,...).
   Nonnegative IPC result copies reply bits23..16 and15..8 into the two byte
   outputs. Set52ddb4 uses(0,40,pin,command,0,40,...), returning0 on negative
   IPC result,1 otherwise. Failed/late replies do not prove that no MCU effect
   occurred. This is not a rollback or physical-state acceptance contract.
6. Aurora DEV_GPIO_SetLevel8516c4 maps physical208 to MCU8 and vendor level0/1
   to command3/2. PLAT_SYS_GetStbcGpio8c66f8 passes the caller's output as the
   first output and a scratch word as the second; DEV_GPIO_GetLevel consumes
   that first output. No direction/level semantic pair was proved for the raw
   reply bytes, so the new API exposes byte16/byte8, not guessed field names.
   Do not mix them with normal GPIO114's cached-direction enum.

The first payload byte was previously ignored by the NDAL wrapper's return
policy. The new helper requires device result1, treating0 as EIO and other
values as malformed. **This is a stricter error-policy deviation**, not a claim
of bug-for-bug vendor failure parity. Raw byte outputs remain unpublished on
failure. EINTR is never replayed. Positive ioctl returns are transport success
only and still require the separate device-result byte.
These errno-style functions are not direct amp_init boolean callbacks; the
future board adapter must map success0 to1 and negative errors to0.

## Device lifetime: recovered facts and open boundary

OpenDevice4db59d10 maps module type10 through category table4db6b744 to1;
node table4db6b834[1]=18hex and format4db6b79c is /dev/video%i, giving video24.
On a fresh category it opens O_NONBLOCK, sets CLOEXEC, marks that category open,
and only when the first argument is0 installs the fd via ndcommon_v4l2_set_fd.
An already-open category skips that branch. This is mutable process-global
state; calling this initializer per module is not an ownership design.

No exported NDAL_VideoExt_CloseDevice was found in the inspected export table;
this is not proof that no internal/other cleanup exists. The lower video24 open/
close lifecycle, coherent fd authority and cold MCU setup remain unresolved.
DRV_STBC_Check/SwitchAGPIOAuthority were inspected but not called; their names
alone do not justify adding an AGPIO or CEC-authority change for normal MCU8.
The prior cold-call reset warning stays in force. Neither getter nor setter
was executed on the TV, and no cause for earlier resets is asserted.
