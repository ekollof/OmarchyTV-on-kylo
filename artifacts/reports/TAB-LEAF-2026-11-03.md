# Tab/settings leaf handlers — 2026-11-03

`common/tab_leaf.c` implements six dispatched handler bodies behind synchronous
owned callbacks: TabDialog volume/digit/removal and qualified SettingsDialog
menu/quit/guide. This fills those method bodies, not the remaining base settings
message map, list handlers, owned renderer/content adapter or queue consumer.

The volume handler asks content interface+18 **isShowing**, not isFocused or
a separate volume-capability/validity flag. TAB-WRITEBACK already resolved that
interface table. If showing, it forwards the original borrowed message through
content+20. It consumes the key regardless of child result. Native source
requires a nonnull content object; our ENODATA guard deliberately bounds absent
content outside valid-tree parity and leaves handled unchanged.

The digit handler reads the raw32-bit field+4b0, computes wrapped
`previous*10 + key - 0x200`, and takes its **signed** remainder modulo10000.
The division helper's signed magnitude/sign correction and wrapper's r1
remainder are established from instructions and executed in the reference;
do not substitute unsigned modulo or undefined signed-overflow C arithmetic.
Our conversion uses defined uint32 wrap and a signed int64 representation.
It stores the remainder bits before any end action. Results0x450 (1104) and
0x1275 (4725) directly invoke qualified SVGDialog::endDialog with resultd1/b5.
They do **not** use virtual endDialog dispatch. The differential first exposed
an unmapped direct call at10c5478 in the test harness; the implementation/API
now preserve this distinction instead of treating every end as interchangeable.
This is not evidence of a TV crash or a hardware failure.

Menu Exit210 virtually ends with29a and does not reset picture selection.
Menu22d/25b/251 resets DemoApp's picture selection first and virtually ends0.
Other keys supplied to this body (including2bb from the parent map) end0 without
that reset. Quit virtually ends0 then pushes a **fresh key event** with the
unchanged key. Guide virtually ends0 then pushes a **fresh navigation event**
with code0xb; this must not be reconstructed as a key event. These methods
consume. Removal checks media-browser state; only a true state virtually ends0
and pushes a fresh key2a7. Its handled truth is the media getter's truth.

Only CONTENT_KEY gets the original borrowed message pointer. Every synthesized
event action gets NULL and requires an owned event from the eventual backend.
SET_DIGITS carries raw remainder bits; it needs retained per-controller state,
not a temporary variable reset between keys. No context/message/callback is
retained by this synchronous layer. Pin ownership and gate permission/lifecycle
in the adapter; an invoked callback does not prove successful UI/hardware work.
END_DIALOG means virtual dispatch, SVG_END_DIALOG the direct qualified method.
