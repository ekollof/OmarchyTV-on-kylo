## Results

### Physical IR — press/release records captured; repeat event not accepted

With the BLAST helper on `/dev/video28` (pid 1881), the owner pressed the
remote. The raw log (the format always prints `aux=` and does not print the
parenthetical labels) contained:

```text
BLAST code=00003056 aux=00 flag=00 -> rc=22 Right
BLAST code=00003056 aux=01 flag=00 -> rc=22 Right
BLAST code=00003056 aux=00 flag=01 -> rc=22 Right
BLAST code=00003853 ... -> rc=19 Down
BLAST code=00003054 ... -> rc=20 Up
BLAST code=00003855 ... -> rc=21 Left
```

The module emits `r.flag ? OA_KEY_RELEASE : OA_KEY_PRESS`; `aux=01 flag=00`
is therefore a second `OA_KEY_PRESS`, not `OA_KEY_REPEAT`. The vendor
`_dev_uart_parse_rc_key` @ `0x0085d7dc` passes the aux pointer but reads only
`flag` (`+0x33`) to choose `0x50`/`0x5e`; `aux` is not read afterward.
`OA_KEY_REPEAT` has no emitter. This run establishes real press/release
records for four keys, not the three event kinds; no OK press was captured.
The IR TODO item stays open.

### Audible output — tone audible, amp mute gate negative

The first run's tone was audible only after `amp-mute 0`; the muted half was
missing, so the earlier "audible amp accepted" claim was premature. A focused
second bundle (`/buffer/oa-amp-20261107`, `mod_audio_amp` `75bbea2e...`, tar
SHA256 `8c326c63053d05ccafb01d8d699c831ecbf88e1cc5c0ebc73aa35e8268614be0`)
ran Init (`result 1`, mute 1) and played the same 440 Hz default-PCM tone: the
owner still heard it. After `amp-mute 0` (`live 0`) the tone was audible
again.

Default-PCM playback is audible, but the Init/mute state does not gate it.
The amp mute pin/path or the PCM route is not the AD82587 speaker path (or the
STBC write did not affect it). The audible-amp acceptance is **retracted**;
register readback, mute gating, volume/balance and standby remain open.

### Panel backlight — negative

Added `panel <0-100>` to the control socket to exercise the service. Commands
returned success and state updated:

```text
panel 50  -> ok, panel percent 50
panel 0   -> ok, panel percent 0
panel 100 -> ok, panel percent 100
```

The owner reported **no visible change** at 50% or even 0%. The direct
`Hal_Pwm_Set_ByChannel` path therefore reports vendor success without visibly
driving this panel. This is an owner-confirmed negative result: the
PANEL-BACKLIGHT/PANEL-CURVE implementation is not backlight acceptance. The
actual `DEV_PANEL`/MCU/`/dev/ntkled` path still needs recovery; do not use the
vendor scalar as proof of brightness.

### Tuner — HAL attempt, no RF acceptance

The run configured `tuner.hw_init=1` and `tuner.backend=hal`. `tuner-scan 1`
reported:

```text
network 1 state 1 progress 25 lock 1 services 3 error 0
strength 0 quality 0 ber 0.00 snr 0.00 unc 4294967295
```

Progress and services are the module's `+25` scan counter, not backend
results; the HAL signal fields are lock 1 / strength 0. No FTA RF source is
connected, so this is not tune/lock signal acceptance. It is also not the
`nim_stub` fixture tuple, so "fixture scan only" is not the right description.
The NIM-DTV IIC code-21 read still logs `failed_step=5` (kernel NACK); the
module starts by design. No RF/lock acceptance is claimed.

### CEC — acquire errno 1, no TX/RX

## IR glibc compatibility fix

The first bundle failed preflight:

```text
./modules/mod_ir.so: /lib/libc.so.6: version `GLIBC_2.28' not found
```

The child CLOEXEC sweep's `fcntl` bound to `GLIBC_2.28` with this toolchain,
while the TV is glibc 2.23. Replaced it with async-signal-safe
`ioctl(fd, FIOCLEX, 0)`, consistent with the kernel's close-on-exec support.
Final `mod_ir.so` requires only `GLIBC_2.4`/`GLIBC_2.9`; the rebuilt bundle
passed preflight and the helper ran.

## Review corrections

Grok's read-only follow-up review (`grok-adversarial-review-2.md`) caught that
the audible claim lacked the muted half and that "repeat" was an annotation,
not an emitted event. This report now retracts both. Its other findings led to:
amp `suspend` rejecting a busy Init with `-EBUSY` instead of joining on the
host loop; panel resume applying an applied 0 and a 0xFF unknown save/restore;
IR child argument formatting moved before `fork`; and the tuner/CEC wording
corrections above. The panel command still runs the vendor ioctl on the host
loop; that remains a documented MEDIUM.
