# SVGImage::create / SVGImage::destroy internals — 2026-11-03

`common/svg_image.c` now implements the two SVGImage methods the row code
uses. **18** native/C cases pass: the shipped `create` (136 bytes at
`0x10c9638`, CRC `0xbdf31b8d`) and `destroy` (60 bytes at `0x10c8ef4`, CRC
`0xcb48ce8f`) bodies are copied verbatim to their own addresses and called
with all sub-calls stubbed, and the ordered traces match the owned C for the
whole 2×2×2×2 create grid plus both destroy runs. Host units, focused
ASan/UBSan, ARM/qemu (the full 1770796-comparison render group is unchanged),
full `verify.cjs` (35 ok lines) and a focused real-TV CPU run all pass.

## Recovered behavior

Aurora MD5 `64c252340d3af6c5d66072611b7bad7a`. Read-only objdump/ELF.

**`SVGImage::destroy(this)`** (`0x10c8ef4`):

1. `SVGWindow::destroy(this)`
2. `SVGSurface::setCleanUISurface(this+0x9c)`

**`SVGImage::create(this, id, rect, parent)`** (`0x10c9638`):

1. `UIWindow::setId(this, id)`
2. `supplier = SVGContext::getImageSupplier(this->ctx)` (ctx at `this+0x68`)
3. `supplier->vtable[2](supplier, id, &resource)` — the supplier returns
   non-zero when the `UIImageResource` exists. **A missing resource returns
   before any rectangle work.**
4. Copy the 4-word rectangle to a stack local.
5. If `parent != NULL`: `parent->getClientRect(&client)` (hidden return
   pointer), then `EASIRect::offset(local, &client)` — x adds to words 0 and
   2, y to words 1 and 3.
6. `SVGImage::imageCreate(this, &resource, &local, parent)`

New module API: `oa_svg_image_create(img,id,rect,parent,ops)` and
`oa_svg_image_destroy(img,ops)` in `include/openaurora/svg_image.h`, with the
vendor calls behind `struct oa_svg_image_ops`.

## Verification method

`tests/svg_image_native.h` maps the two bodies at `0x10c8000`/`0x10c9000`
(their original addresses, so the encoded `bl` targets resolve to stubs placed
in place), backs their stack-guard literals with an owned canary, and copies
`EASIRect::offset` verbatim at `0xd2af88`. The image supplier is a fake guest
object at `0xe4c000` whose vtable slot 2 (`+8`) points to a saved-register
stub, so the shipped virtual dispatch is exercised rather than bypassed.

Cases: supplier result {0,1} × parent {none, present} × id {0,0x37} ×
rectangle {10,20,30,40 / zeros} = 16 creates, plus 2 destroys. Each compares
the full ordered trace: setId, supplier lookup, resource gate, client-rect,
imageCreate (with the resource identity and the final rectangle words),
window-destroy and clean-surface (with the `this+0x9c` argument).

Two details worth recording: the resource buffer is opaque (the supplier stub
fills a token), and the trace compares *identity* (the resource pointer passed
to imageCreate equals the buffer the supplier wrote) rather than a stack
address, so both sides remain comparable.

**Boundary:** `SVGImage::imageCreate` (`0x10c9430`, the 520-byte
SVGSurface/UISurface/drawImageResource subsystem, including
`drawImageResourceScaled`, tiling, scaling and `UIWindow::create`) remains an
ops callback. `SVGWindow::destroy`, `SVGSurface::setCleanUISurface`,
`UIWindow::setId`, the image supplier and `getClientRect` are vendor calls
behind the ops too. So this slice verifies create/destroy orchestration, not
the actual SVG rasterisation/actor machinery. That, plus row construction,
child visibility internals, live resources, scrollbar/skin, display/scanout
and independent startup, remains open.
