## MxLWare command buffer

`MxLWare601_API_ConfigDevice` @ `0x00880484` and
`MxLWare601_API_ConfigTuner` @ `0x00880974` take a word array:

```text
+0x00  command
+0x04  byte I2C address (0xc0)
+0x08  param[2]
+0x0c  param[3] (some commands store only a byte)
+0x10  param[4]
+0x14  param[5]
+0x18  param[6]
+0x1c  param[7]
```

`SAL_TUNER_MxL661_Init` @ `0x00872968` reuses one stack buffer for the six
commands, so fields a command does not write can retain the previous command's
value (see the IF-out branch below).

## Low-level register access

`Ctrl_WriteRegister` @ `0x0088031c`:

```text
DEV_IIC_Write(0, 4, addr, 1, reg, 1, &value)
```

It returns 0 on success (instruction-level: `movs r0,#0` on the success path),
nonzero on failure. `Ctrl_ReadRegister` @ `0x0088039c`:

```text
DEV_IIC_Write(0, 4, addr, 1, 0xfb, 1, &reg)
DEV_IIC_Read (0, 4, addr, 0, 0x20000000, 1, buf)
```

It returns 0 on success. `Ctrl_ProgramRegisters` @ `0x008822dc` walks 3-byte
`{reg, mask, value}` entries:

- `00 00 00` terminates;
- `mask == 0xff` skips the read and writes `value`;
- otherwise it reads `reg`, writes `(old & ~mask) | value`;
- a failed read/write stops the remaining entries.

`MxL_OverwriteDefaults` @ `0x017683c4` is 26 entries (all mask `0xff` in this
firmware):

```text
00 ff 01, 96 ff 00, 00 ff 00, 14 ff 13, 6d ff 8a, 6d ff 0a,
df ff 19, 45 ff 1b, a9 ff 59, aa ff 6a, be ff 4c, cf ff 2a,
d2 ff f5, d0 ff 34, 77 ff e7, 78 ff e3, 6f ff 51, 7b ff 84,
7c ff 9f, 56 ff 41, cd ff 64, c3 ff 2c, 9d ff 61, f7 ff 52,
58 ff 81, b1 ff 30
```

`gTunerDefaultConfig` @ `0x01368330` is 11 words:

```text
1, 0, 0x0b, 0, 0, 0, 6, 1, 0, 1, 1
```

The init mapping is `[0]` power-supply/xtal/0x0e enable, `[1]` xtal freq,
`[3]` clk-out enable (also the stale IF-out selector), `[4]` clk-out div,
`[5]` xtal sharing, `[6]` IF path, `[7]` AGC type, `[8]` xtal cap/divider,
`[9]` AGC id, `[10]` AGC type. `[2]` is not used by these six commands.

## SAL type-0xd init order

For the shipped default config the recovered sequence is 41 register writes
and 5 read-modify-write reads:

```text
1  SOFT_RESET          reg 0xff = 0
2  OVERWRITE_DEFAULT   26 table writes; reg 0 = 1; read 0x31;
                       reg 0x31 |= 0xd0; reg 0 = 0; reg 0x0e = 4
3  XTAL_SET            1 = ((cfg[3]<<7)|(cfg[1]<<5))&0xff | cfg[8]&0x1f;
                       2 = (cfg[4]&1) | (cfg[5]==1 ? 0x40 : 0);
                       0x6d = cfg[5]==1 ? 0x80 : 0x0a; 0x0e = 0x14
4  IF_OUT              read 4; 4 = (v & 0xc0) | cfg[6];
                       5 = ((cfg[7]&3)<<4 | 0x0b) + (cfg[8]==1 ? 0xc0 : 0)
5  AGC                 read 8; 8 = (v & 0xf2) | cfg[10] | (cfg[9]<<2);
                       read 9; 9 = (v & 0x80) | 0x42;
                       read 0x5e; 0x5e = v & 0xef
6  POWER_UP            reg 0x0b = 1
```

The AGC constants `0x42` and the zero `param[5]` (hence `v & 0xef`) are
hardcoded by `SAL_TUNER_MxL661_Init`, not taken from the config.

### Stale-buffer IF-out branch

`ConfigDevice(IF_OUT_CFG)` checks `param[4]`, but the IF-out command never
writes `+0x10`; it still holds `cfg[3]` from the XTAL command. When
`cfg[3] == 1` the vendor takes a different branch:

```text
read 4; 4 = v | 0x20;
u = ((param[3] & 0x7ffff) << 7) / 0xd2f;   // param[3] low byte = cfg[8]
6 = u & 0xff; 7 = (u & 0xfff) >> 8
```

The shipped config has `cfg[3] = 0`, so this TV uses the else branch. The
implementation models both branches; for the non-default branch it uses the
low byte of `cfg[8]` because the vendor's upper `param[3]` bytes are stale
stack data. That deterministic choice is documented rather than presented as
firmware-exact garbage.

## HAL tuner bus/read/write ABI

`HAL_TUNER_Init` @ `0x0084c164` only resolves bus IDs. For each global still
`0xff` it calls `DEV_IIC_GetDescription(0..3)` and reads byte `+0x19`:

| index | use | global |
|---|---|---|
| 0 | tuner | `0x0175eb78` |
| 1 | sat tuner | `0x0175eb76` |
| 2 | ext demod | `0x0175eb77` |
| 3 | LNB | `0x0175eb75` |

A missing description falls back to bus 0. `HAL_TUNER_WriteBase` @
`0x0084c304` and `ReadBase` @ `0x0084c364` build a 0x18-byte context
`{bus, reg, 0, 0, 400, 0}` and call `Hal_Iic_Write/Read(ctx, &zero_byte, len,
buf)`. Success is `rc == 0`; the ARM return is `clz(rc) >> 5`.

## Implementation

- `common/mxl661.c`, `include/openaurora/mxl661.h`: default config, defaults
  table, the six-command init, both IF-out branches, read-modify-write masks,
  and vendor failure behavior (failed table entry stops that table; later
  commands still run; the function returns nonzero if anything failed).
- `common/tuner_hal.c`, `include/openaurora/tuner_hal.h`: four bus IDs from
  description `+0x19` (only unresolved `0xff` entries), and the base
  read/write context/return contract.
