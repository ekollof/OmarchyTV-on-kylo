## Instruction-derived contract

DynamicUILoader::loadFontData ef5194 reads the index count/record lengths and
consecutive binary records, checking the total against the file size.
UIBitmapFont::decodeFonts115e424 tests the EF header before calling the encoded
font factory; byte0 sentinel selects the default font. Constants0154f580 are
`EF`, `SYS`, `FT` (two/three/two bytes). The target pack has39 records: sentinel0
and38 EF41 encoded fonts. Other factory branches exist; their mere presence
does not establish usage for the current settings rows.

hal::BitmapFont::decodeBitmapFont b428d4 / helper b422f8:

- Header EF41: version4, grayscale flag1; BE32 pixel-data length at+4;
  raw pixel data starts+8.
- After pixels, `UTF`, BE16 key count, BE32 packed UTF8 keys.
- Then `DIM`, BE16 glyph count, nine-byte records and one nine-byte extremes
  record. Each glyph is five signed bytes top,left,bottom,right,advance and
  BE32 offset relative to pixel-data start. In-memory vendor metric records
  are12 bytes; serialized records are9. Do not apply the object stride to files.
- getPrintableCharacterFromUTF8 b4267c maps ASCII32..126 directly to internal
  char codes, and bsearches the packed UTF8 table for non-ASCII; found key k
  gets internal code127+k. getGlyphDataForChar b4233c subtracts32, hence array
  index95+k. These are packed UTF8 bytes, not Unicode scalar values.
- DrawContext::drawGreyScaleGlyph b43ea0 uses signed metrics and raw8-bit
  coverage. Width=right-left, height=bottom-top, tight stride=max(width,0).
  No RLE decoding. Firmware b43f44..4a and its inner loop use signed bounds;
  nonpositive extents consume no coverage pixels.

Font24 includes five glyphs with wrapped signed extents (indices273,322,569,
570,583). Keeping signed metrics and blank-loop semantics allows these records
without interpreting negative sizes as huge unsigned allocations. This is
observed pack behavior, not an invented correction to glyph designs.

## Implementation and checks

common/font_bitmap.c + include/openaurora/font_bitmap.h borrow immutable
storage, allocate nothing and reject unsupported encodings. Bounds, exact
record extent, glyph/key relation, key ordering and all accessed coverage spans
are checked before publishing a view. No guessed substitution for absent keys.
Legacy/monochrome encodings and other version numbers remain unsupported.
Caller supplies packed UTF8 keys; this is not a full UTF8 text parser.

truncated length, negative metrics, blank extents, bad offsets/key order and
ASCII/non-ASCII lookup. The same executable optionally takes pack and index
