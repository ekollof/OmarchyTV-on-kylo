# Owning worker for injected amplifier Init — 2026-11-04

`common/amp_owner.c` runs the blocking AMP-INIT sequencer on a single owning
thread. It has no native backend, fallback device open or module integration.
All work was offline under the owner's prohibition on TV access.

## Lifetime and completion contract

- Creation copies the explicit initial image/cache and the callback table.
  Submission copies the profile scalars and NUL-terminated power name (up to
  31 bytes). No caller-owned profile/name/table storage is used asynchronously.
- Callback code, backend context and returned GPIO records remain borrowed
  until a successful join. Callbacks execute outside the owner mutex, on the
  worker. There is one pending request or one untaken value completion.
- Completion copies the post-Init image/cache and native return, including
  write failure. The worker retains its own state for subsequent submissions;
  caller changes to completion copies cannot alter it. Tickets are scoped to
  one owner instance and are not public reload-stable identifiers.
- Quiesce rejects new submissions, drains accepted work without cancellation
  or replay, and tries to join without waiting. It remains busy through thread
  TLS destructors. Join errors retain ownership; destruction refuses a thread
  that has not been joined. An idle shutdown invokes no hardware callbacks.
- Inherited handles reject `-ECHILD` before locking. Quiesce/join/destroy must
  be serialized, and destruction must not race other calls. Completion remains
  available after join; destruction explicitly discards an untaken result.

This is project scheduling policy, not a claim about vendor thread behavior.
Init's underlying firmware comparison remains the 29,952 controlled cases in
AMP-INIT. Its native return only reports the write-loop result, not audibility.

Instructions at `46f066cc` check the thread's live TID at offset104 and return
EBUSY before joining if nonzero; no condition wait is used. Symbol/disassembly
evidence is in `artifacts/analysis/amp-owner-2026-11-04/target-pthread.txt`.
Library SHA256: `0513b8f140823c98125b6321b7e1fe6855e1fc9f59ddc0597db9ca57872a5d8f`.

`check-amp-owner` passes strict host, leak-enabled ASan/UBSan and fresh ARM/qemu
(`TARGET=tv BUILD=build-tv-v3/amp-owner`). Its four groups test copied inputs,
worker-only callbacks, pending and untaken-result backpressure, retained image
after write failure, value-result isolation, accepted-work draining, fork
rejection, a blocked real TLS destructor, injected join failure and idle exit.
The fixture observes real condition waits and uses the real nonblocking join;
only the explicit error case replaces a join result. Delay callbacks do not

Evidence logs are in the same analysis directory. ARM unit SHA256:
`d579fdfa7c2f242399fb272847e57c6d67d8fa423fcf3f86c37a0e0651ca38a4`.

The owner subsequently allowed TV tests that do not use active fb1. The exact
60,756-byte ARM unit above was staged at `/tmp/oa-amp-owner-fb4a1c1`; size and
SHA256 were independently checked over a second successful connection before
execution. All four groups passed with the actual TV glibc/pthread, including

Callbacks are injected: no GPIO, MCU, I2C, audio or framebuffer device is opened;
there is no physical amplifier test and fb1 was not accessed.

remaining helper. Before/after boot ID was
`71f7eb63-727f-4b9a-a9c7-2b04dc3f9197`, Aurora PIDs remained1967/1785 and

Offline continuation research is in `artifacts/analysis/amp-state-2026-11-04/`.
Fresh references to image base017640e8 identify Init and IsAlive; they are not a
complete proof that no interior-byte references exist. The existing complete
Create disassembly in cec-ownership-2026-11-01/ad82587-contract.txt confirms
private reset cache0/mute cache1 at private+4/+5 (875718/87571c), not two zero
bytes. Create does not copy/reset the process-global image. Thus a future seed

reinitialization/reload; loading the ELF again cannot recover the currently
running owner's state. No seed-loader implementation or new lifecycle gate is
claimed by this research.
