# Asynchronous CEC-owner requests

The lower owner now accepts acquire/send/receive/release_async and provides
take() value results. It uses the same fixed one-request/result-slot model as
AUDIO-ASYNC. Submission returns an instance-scoped ticket without waiting for
device I/O. New requests and legacy synchronous RPCs reject while the slot is
occupied. Result collection consumes exactly once; pending take leaves caller
output unchanged. Tickets reject overflow and cannot cross destruction/reload.

Acquire copies the path and authority/device callback tables. This API bounds
the copied path to255 bytes plus NUL; that is an internal queue limit, not a
claim about Linux pathname limits or vendor ABI. Invalid tables reject before
authority access. A second acquisition rejects before authority access or
overwriting an active session's backend. The copied device table remains stable
through later jobs and failed hardware-close attempts. Callback context/code
are borrowed until release or successful quiesce+join.

Send copies the validated TV frame. Receive never borrows caller output: its
result is1 decoded frame,0 empty, or-1 error. Positive receive success carries
error0 regardless of stale worker errno. Nonreceive/empty/error result payloads
are zeroed. No user completion callback is retained; the loop polls take().

Quiesce rejects new work and drains an accepted request before closing. Failed
hardware close retains fd and copied backend, without claiming exit/settlement,
until another explicit quiesce generation retries successfully. Untaken receive
results survive those close attempts and join, until destruction. This does
not forcibly cancel a blocking ioctl; native completion/cancellation requirements
remain open. Final OS-close consumption semantics are unchanged.

The legacy synchronous waiter loops in both audio and CEC also stop waiting if
an async request wins the slot, rather than waiting behind that async operation.
Operation enums map directly to public completion-operation values.

Four injected-I/O groups in tests/cec_async.c pass strict host, ASan/UBSan,
ARM/qemu and actual TV. They cover blocked acquire, copied table/path lifetime,
invalid callbacks before authority, bounded backpressure, copied send, decoded
and empty receives, retained failed release, rejected reacquisition, and shutdown
during blocked receive with multiple failed-close generations and untaken result.
Full host make check passes, as do focused owner/race/policy/quiescence/audio
sanitizer groups. Explicit ARM/qemu runs also cover legacy CEC and audio async.

No new firmware call or wire-policy rule was invented: the existing decoded
raw device/authority helpers remain the execution layer. This change is worker
lifetime/marshalling, not a CEC conformance certification or native bring-up.
