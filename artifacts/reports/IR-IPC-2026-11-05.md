# IR module real-socket lifecycle — 2026-11-05

Offline acceptance for `mod_ir` as a reloadable module. The test starts the
real `openaurora` host with a Unix control socket and the recorder display
fixture, not a TV or HAL device.

## Setup

`tests/ir_ipc.cjs` copies:

- `mod_plat.so` (host fixture prelude)
- `mod_ir.so`
- `mod_ui_engine.so`
- `mod_ui_vendor.so`
- `tests/ui_nav_display.so` as `mod_nav_display.so`

Config: `ui.dir` empty, `ui.live_cards=0`, `ui.paint=1`, `ir.device=` and
`ir.blast=0`. The UART and vendor BLAST library stay unopened; key frames are
fed by the control `key <code>` command through the shipped parser.

## Covered

- load/start `plat`, `nav_display`, `ir`, `ui_engine`, `ui_vendor`
- `status ir` reports `state started` and `input:v1`
- `key 22` reaches `ui_vendor` and repaints the portal
- `stop ir` makes `key 22` return `failed errno 19` (ENODEV)
- `start ir` restores the key path
- `reload ir` republishes `input:v1` and still accepts keys
- `reload ui_vendor` while input is live, then `key 21` still works
- `stop`/`start ui_vendor`, then another key
- `unload ir` / `load ir` / `start ir`, then another key
- clean `SIGTERM`, zero exit and socket removal

The existing `tests/ui_vendor_ipc.cjs` separately covers the recorder/display
and `ui_vendor` stop/start/reload/display-provider reload/unload lifecycle.

## Commands and result

```
make -j24 check-ir-ipc check-ui-vendor-ipc
ok actual ir control-socket lifecycle: start/key/stop/reload/unload and ui_vendor reload
ok actual ui_vendor/display Unix IPC: start/use/stop/reload/display-provider reload/unload lifecycle

make -j24 check-ui-nav
ok full-screen portal follows remote frames; focus survives reload
```

## Limits

Host recorder and fixtures only. `ir.blast=0` deliberately excludes the vendor
BLAST/ALSA/libv4l2 path, so this proves module lifecycle and the UART/parser
control path, not physical IR or the TV's `/dev/video28` backend. No TV access;
full `make check` was not rerun for this focused test addition.
