# IR helper framing, CLOEXEC and reap — 2026-11-07

Scope: fix the HIGH IR findings from AGENT-REVIEW-2026-11-07 in the BLAST
helper path and pin the wire record. Host/offline work only; no physical remote
press was available and no TV access was needed.

## Findings and fixes

### 1. Unbounded read desynced the record stream (fixed)

The old `blast_helper_read` read up to 64 bytes into a temporary buffer, then
did `if (blast_rxn + n > 64) blast_rxn = 0` before copying. With 7 bytes of a
record pending, a 64-byte read discarded the pending bytes and parsed the rest
from an unaligned offset; the stream could also lose whole records.

Fix: read directly into the free space of the assembly buffer
(`room = 64 - blast_rxn`). The loop still drains every complete 8-byte record.
The buffer size is a multiple of the record size, so a bounded read cannot
leave `room == 0`; the defensive reset only covers a future layout change.

Regression (`check-ir-helper`): write 7 bytes, read (pending = 7), then write
the last byte plus eight records (65 bytes) and drain. The old behavior emits
fewer/misaligned keys; the fixed path emits all nine with the expected
code/kind. Temporarily restoring the unconditional 64-byte read + reset makes
the test fail at `nevents == 9`.

### 2. Record layout is 8 bytes on ARM (pinned)

`struct oa_ir_blast_record` is `uint32_t code; uint8_t aux; uint8_t flag;` and
the ARM EABI pads it to 8 bytes. The old header did not state this, and the
review noted the docs said 6.

Fix: the header now has `_Static_assert` for size 8 and offsets
`code=0/aux=4/flag=5`; the helper `memset`s the record before filling it so
the two padding bytes are deterministic on the wire. The module and helper both
transfer `sizeof(record)`.

Evidence: an ARM-compiled probe object exposes
`ir_record_size_probe` with symbol size 8:

```text
00000000 00000008 B ir_record_size_probe
     9: 00000000     8 OBJECT  GLOBAL DEFAULT    3 ir_record_size_probe
```

### 3. Inherited fds lacked close-on-exec (fixed)

The helper is forked from the host and execs `oa-ir-blast`; it inherited the
host's `/dev/mem`, GPIO, UART and module sockets.

Fix:
- `open_port()` opens the UART with `O_CLOEXEC`;
- the helper pipe already used `pipe2(O_CLOEXEC)`;
- the forked child calls `mark_inherited_fds_cloexec()` immediately before
  `execl`: it walks the descriptor range from 3 to `sysconf(_SC_OPEN_MAX)`
  (capped at 65536, `ioctl(FIOCLEX)` only) and sets close-on-exec on
  every open descriptor above stderr. This uses only async-signal-safe calls;
  an `opendir`/`strtol` sweep would risk a malloc lock in a forked
  multi-threaded host. `dup2` to stdout keeps fd 1 open.

Test: clear `FD_CLOEXEC` on a `/dev/null` fd, run the sweep, assert the flag
is set again. Removing the sweep body makes the test fail at that assertion.

### 4. Helper stop could block forever (fixed)

The old stop did SIGTERM + 20×5 ms `WNOHANG`, then SIGKILL and a **blocking**
`waitpid(pid, ..., 0)`. A helper stuck in an uninterruptible vendor call would
freeze the host loop.

Fix: `reap_child_bounded()` only uses `WNOHANG` and a bounded 5 ms poll
(20 attempts = 100 ms). Stop sends SIGTERM, waits up to 100 ms, sends SIGKILL,
waits up to another 100 ms. If the child still survives, the pid is retained
and a later stop/destroy/start retries; no blocking wait exists. `ECHILD`
counts as already reaped, and a deferred pid is cleared by EOF handling or the
next start once it is gone.

Tests: `reap_child_bounded` on a live SIGTERM-ignoring child returns 0 after a
bounded wait; SIGKILL then reaps it. `blast_helper_stop` on the same child
completes in ~113 ms (SIGTERM budget, then SIGKILL) and leaves `ECHILD`.
The old blocking `waitpid` would not return for a child that never dies; the
new code cannot.

## Limits

- Physical press/repeat/release was captured later for four keys
  (Right/Down/Up/Left; HW-ACCEPT). Full key-map/OK coverage and the
  repeat-emission mapping (`aux=01`) remain; this report's parser/helper
  correctness is not full remote acceptance.
- The helper still depends on the vendor `libNDAL_EX` BLAST_RX and the
  `/dev/video28` mapping in `ir_devices`/TAKEOVER-IR; none of that changed.
- The 200 ms bounded stop budget is a policy choice. A helper stuck longer is
  retained for retry, not force-reaped.
- No automatic acquire retry for MCU UART frames; the UART path is the existing
  fallback.
