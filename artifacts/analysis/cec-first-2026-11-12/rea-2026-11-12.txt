Ghidra 12.2 at `/opt/ghidra`. Installed with
`npm install --ignore-scripts` under `/tmp/opencode/rea-eval`; no
`rea setup`, no repo dependency, no canonical Ghidra project opened.

## Ghidra provider: handleCECMessage

- procedure: `NovoCECController::handleCECMessage`
- address: `0x102fce0`
- body ranges: `0x102fce0..0x102ffd7`, `0x102ffe0..0x10302ed`,


```text
0x103016a: ldr r1, [r4,#0x4c]
0x103016c: cmp r1, #0x3
0x103016e: bne 0x01030138
0x1030170: b 0x0102fd0a
```

The 0x9D path requires 2 operands, the sender to be the current external
source, and the device power status not to be 3. It then checks the TV's own
`+0x4c` state: when that is not 3 it exits to `0x01030138`; when it is 3 it
takes `0x0102fd0a`. It does **not** clear the active source or select a tuner.

The 0x82 pseudocode path calls `selectSource(this,param_1)` after its OLED /
quick-standby checks. That is consistent with the owner's resume-to-HDMI1
observation; the sleep tuner fallback is more likely the HDMI hotplug /
source-loss path. This corrects the 0x9D row in
`CEC-SPEC-VS-AURORA-2026-10-30.md`.

## ARM objdump provider

The host `objdump` reports `can't disassemble for architecture UNKNOWN` for
the ELF32/ARM module. Setting `REA_OBJDUMP_COMMAND` to
`artifacts/workbench/gcc-arm-10.2-2020.11-x86_64-arm-none-linux-gnueabihf/bin/arm-none-linux-gnueabihf-objdump`
works:

```sh
REA_OBJDUMP_COMMAND=.../arm-none-linux-gnueabihf-objdump \
  rea inspect-with-objdump ntkdriver_nondovi.ko \
  disassemble --symbol _CEC_TX_Data --format json
```

The output begins at `000ca188 <_CEC_TX_Data>` with the same instruction
sequence as the Ghidra dump (`0xda3b0` runtime / `0xca188` section-relative):
`mov ip,sp`, `push {fp,ip,lr,pc}`, `sub fp,ip,#4`, ... and the final
`str r3,[ip,#0]` write to register `+0`.

## Limits

- REA imports its own private Ghidra copy; it does not reuse the canonical
  `ghidra_*` projects or our saved names/annotations.
- Pseudocode control flow needed an exact instruction check; do not treat the
  decompiler's `goto` structure as proof.
- Only static providers were used. No debugger, process capture, runtime
  provider, firmware extraction or TV access was performed.
- REA is not a repo dependency. Pin `6.9.0`, use a temp prefix, and keep
  outputs as leads until verified in our Ghidra/objdump workflow.
