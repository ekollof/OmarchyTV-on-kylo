# tvsim — offline stand-in for the TV (2026-10-30)

Testing the launcher used to mean waking the TV, loading the page over DIAL and reading screenshots.
`tools/tvsim.py` emulates **the control plane the launcher talks to** and drives a real browser, so the
UI loop can be exercised with the set asleep (or absent).

## What it emulates

| piece | real TV | tvsim |
|---|---|---|
| static host | busybox httpd on the TV, `:8181` | repo `launcher/` served on `:8181` |
| `/cgi-bin/act` | shell CGI → DIAL key POSTs | re-implemented in Python; executes the *same semantics* |
| `/cgi-bin/stats` | TV `/proc` | host `/proc`, host name `tvsim` |
| `/cgi-bin/net.js` | eth0 + IP | `eth0 · 10.0.0.2 up (sim)` |
| DIAL | aurora + dialserver, `:56789/56790` | minimal server: `dd.xml`, `POST /apps/SmartCenter` (201) |
| state feed | `ws://<tv>:7681/` | `ws://127.0.0.1:7681/`, pushes `<tv_state value='...'/>` |
| screen | 1920×1080 framebuffer, 1280×720 CSS @DPR 1.5 | headless Chromium + CDP device metrics → screenshots are 1920×1080 |
| remote | IR → ICE → DOM events | DIAL key code → CDP `Input.dispatchKeyEvent` |

TV-control keys behave like the set: `1012` (power), `1010/1037` (exit), `1048` (menu) and `1056`
(source) **close the page** instead of reaching the DOM, and `browserseturl` navigates.

## Usage

```sh
tools/tvsim.py                 # servers + headless browser, then: ready
tools/tvsim.py --headful       # same, visible window (handy while editing the UI)
tools/tvsim.py --no-browser    # only the HTTP/WS side; open http://127.0.0.1:8181/omarchy/ yourself

tools/tvsimctl.sh key 1022     # remote key by DIAL code
tools/tvsimctl.sh load         # what browserseturl does
tools/tvsimctl.sh shot /tmp/x.png
tools/tvsimctl.sh state        # PORTAL / SOURCE / STANDBY
tools/tvsimctl.sh dial "<remote><key code='1048'/></remote>"   # raw DIAL payload
```

The simulator prints a transcript, which is also a nice artefact for a bug report:

```
16:04:42 key 1022 (ArrowRight): dispatched to the page
16:04:43 key 1053 (Enter): dispatched to the page
16:04:43 tile: Sources -> source list
16:04:45 browserseturl: http://127.0.0.1:8181/omarchy/
```

## What it caught / proves

* the page renders correctly at **1280×720 CSS / DPR 1.5** (screenshot 1920×1080, same framing as the TV),
  which is the scaling trap that clipped the UI earlier;
* the dock/tile navigation reacts to injected keys exactly like the set (RIGHT moves focus, header and
  hint follow);
* the tile → CGI → "TV takes over" transition (page closed, state `SOURCE`) and the return via
  `browserseturl` (state `PORTAL`);
* the boot handshake (`a=boot-ok`) and the page heartbeat (`a=alive`) that the hook's watchdog uses.

## What it cannot test

DirectFB/OSD rendering, the video plane, audio, the real aurora/Dial quirks (e.g. the transient Bronlijst,
keys the app swallows), standby/WoL, the stock-portal tile, or the actual browser engine — this is
Chromium 13x, not the TV's 67. Use it for the web UI and the integration logic; keep the TV for anything
that touches the platform.
