  `/vendor/ice_keymapping_db.xml` (internal ICE variants), `/vendor/dial_appname_to_prefixurl_list.xml`

  Codes: digits 0–9 = 1000–1009, `KeyExit` 1010, `KeyPower` 1012, MUTE 1013, VOL_UP 1016, VOL_DOWN 1017,

## Safety rules
- **Any process crash resets the set, by design** (measured 2026-10-31): the kernel core pattern is
  `| /usr/sbin/core_helper.sh gzip %p %e %t`, and that script — when `/conf/coredumpnoreset` does not
  exist — calls `before_system_reset` (umount + `ubidetach` `/mtd_rwarea`, `/conf`, `/buffer`) and then
  `pcbconfig -i -w 1`, i.e. it arms the MCU watchdog at **1 s** with nothing left to kick it. That is
  what "the TV bricked" looked like every time a probe segfaulted
  (`/conf/always_logging_reset_count` counts them). **`/conf/coredumpnoreset` is the documented
  off-switch** (it makes the handler call `pcbconfig -i -w 0` instead); it is set on this set for
  development. **Verified**: with the flag set, a deliberate `SIGSEGV` left the set running (uptime kept
  advancing, `always_logging_reset_count` 2→3, `dmesg` showed `[COREDUMP] SIGNR:11`, aurora and DIAL
  still up). `/conf/enable_coredump` controls whether cores are written to USB at all.
- The same file explains the other boot-time reset path: `/vendor/run.sh` starts `trigger_reboot &`,
  which waits for `/tmp/trigger_reboot` and then `pkill -f aurora.elf`, `pcbconfig -i -w 10`, detaches
  the partitions and runs whatever command the file names. Not a supervisor — a trigger.
- **The MCU watchdog is controllable from userspace** (`artifacts/reports/PANEL-TAKEOVER-2026-10-31.md`):
  vendor aurora is what feeds it, so `SIGSTOP`/`kill` of aurora used to reset the SoC. Run
  `/buffer/wdtctl disable` first (tool: `openaurora/tools/mcu/wdtctl.c`) and the set stays up with
  aurora stopped. It writes the 6-byte packet `{0,0xae,0,0,0,0xae}` to `/proc/nvtstbcipc`
  (`{0,0xae,hi,lo,1,0xae}` = set timeout). Do **not** try to reach the watchdog through
  `libNDAL_EX`'s `NDAL_VideoExt_STBC_*` calls — that resets the set (half-initialised MCU path).
  With the watchdog disabled, killing aurora leaves it dead (appmgr does not respawn), so a reboot
  is how you get the stock UI back.
- Signed/verified at boot: `fs0`, `ap0`, `ap1` (`nvt_sign` volume; kernel `rootflags=nvt_security` → "UBI Security Verify volume Fail … goto shutdown"). **Never patch them** — the TV will refuse to boot.
- Safe write target: `apdat0` (`/conf`), unsigned, UBI volume 31 × 253,952 B at NAND `0xe340000`. Always keep `apdat0_orig.ubifs` for revert.
- U-Boot auto-script channel (`hold OK` + `kylo_usb_update.scr`, <8 KB, must end with `%`) is the recovery path; it lives in xboot/U-Boot which we never write.
- Keys change on-screen UI — visible to owner. Prefer SSRF/WS/description reads. If keys sent, close with `EXIT,EXIT` / `BACK`.
- Never flash firmware without exact `VESxxx` panel match + official `upgrade_mb230.bin`. Encrypted + Secure Boot on MB230; mismatch = brick.
- No long MITM: 60s targeted `arpspoof -t <tv> <gateway>` max, IP forwarding on, stop afterwards. Prior capture was empty — don't repeat without reason.
- Firmware is copyrighted (Vestel/Telefunken). Don't redistribute dumps. Request via `service.vestel.com / telefunken.com/service` with model+serial+panel.
- Kill background probe servers in `/tmp/opencode/exfil*.py` when done (use exact `pkill -f` in a separate shell call to avoid self-kill; the `[e]` trick still matches later args in same command line).
- On this host `ssh` is wrapped with OnConnect hooks that break non-interactive command execution — use `/usr/bin/ssh -F /dev/null …`.

## Firmware is the source of truth (rule added 2026-10-30)

The vendor binaries and libraries ship **unstripped**, so most questions have an authoritative
answer before anything is run on the set. Read it first:

* extract the file from the dump — `artifacts/scripts/extract_from_dump.sh vendor:/lib/<lib>` /
  `root:<path>` (no TV needed);
* open it in Ghidra — `/tmp/opencode/ghidra_proj` has `aurora.elf` analysed,
  `/tmp/opencode/ghidra_ndal3` has `libNDAL3.so`;
* `libNDAL3.so` (643 `Hal_*`) and `libNDAL_EX.so` (160 `NDAL_*`) are the only reusable vendor
  surface; `PLAT_*`/`DEV_*`/`ICE_*` live inside `aurora.elf`.

**Check Ghidra/disassembly before trying anything on the set** (rule added 2026-10-31). Before a
reboot, a device probe, an ioctl, or any "let's see what happens": answer the question from the
binaries, the driver or the kernel first. Scripts are in `/tmp/opencode/ghidra_scripts`
(`DumpStringXrefs`, `DumpFuncs`, `DumpCallers`, `DumpPltCallers`), and `analyzeHeadless` is at
`/opt/ghidra/support/analyzeHeadless` (Java scripts only — no Jython). Two cases from 2026-10-31 that
cost reboots: framebuffer registration, device-node creation and OSD presentation
were conflated. **Corrected by driver decompilation:** KER_OSD_DrvInit allocates
and registers all five framebuffers; visible enable/commit is a separate path
(`artifacts/reports/OSD-KERNEL-INIT-2026-10-31.md`). Also, the
32-byte OSD region layout is fixed by `NVTGA_OSD_SetRegion`. On-set probing is for *confirming* what
the code already predicts — and prefer reading driver state back (`tools/mcu/fbregion.c`) over
drawing test patterns.

**Probing on the set is for confirming behaviour, never for discovering an API.** The PWM episode is
the cautionary tale: `Hal_Pwm_Set_ByChannel` was assumed to take a three-word
descriptor, omitting its mode word. The recovered request has four words
`{freq, duty, shift, mode}`, with mode < 9. **Return correction (2026-10-31):**
the saved Ghidra prototype says void, but ARM return instructions prove a scalar
result (r6 → r0 at 0x4e7c1056); Open likewise returns r8 → r0 and reads six words.
The result alone is not a hardware-write acknowledgment. Use the maintained
`openaurora/include/openaurora/vendor_pwm.h` and
`artifacts/reports/PWM-CONTRACT-RECHECK-2026-10-31.md`, not older void-return claims.

Same for the display: the fbdev/tdga ioctl set was read out of `libdirectfb_tdga.so`, which is why
`FBIOPAN_DISPLAY` and the region ioctl were known before touching the panel.

The firmware is also immutable for us, so the extracted libraries are a stable link target
(`openaurora` links them directly; see `openaurora/docs/ARCHITECTURE.md`).

**Everything, including `/conf`, is in the dump.** `apdat0` (`/conf`) is not one of the volumes
`extract_from_dump.sh` knows, but it is carved from the same image:

```sh
python3 -c "d=open('artifacts/dumps/tv_nand.bin','rb'); d.seek(0xE340000); \
            open('/tmp/apdat0.bin','wb').write(d.read(0xA00000))"
/tmp/opencode/venv/bin/ubireader_extract_files -o /tmp/apdat0_x /tmp/apdat0.bin
# -> /tmp/apdat0_x/<id>/apdat0/  … settingsDB.db, mb230_hwprofile.bin, PCF.pcf, PQF.bin, …
```

Verified: the dump's `mb230_hwprofile.bin` is byte-identical (md5 `1b063b2c…`) to the copy pulled from
the running set, so device data never needs the TV to be awake. The live `settingsDB.db` differs from
the dump only by our own edits (privacy flags, the OmarchyTV tile).

**Parity first, then change it.** openaurora's first target is to behave exactly like the vendor
`aurora` — same screens, same remote behaviour, same assets — and only then to diverge on UI/UX. That
means the *content* comes from the firmware too, not from guesswork:

* **theme / chrome / artwork** — `/vendor2/dynamic_ui` (`default.ui`, `telefunken18_{svg,img,font}.bin`
  + their `.txt` indexes), plus `/buffer/logo.jpg`, `/buffer/bootlogo.jpg` and the app tile icons
  referenced from `settingsDB.db → LauncherItem`;
* **strings / labels** — the `slim_i18n` tables and the `NovoSystemInformationProvider` getters
  (`getHdmi1Name`, `getExt1Name`, …) that feed the source list;
* **key behaviour** — three pieces, all in the firmware:
  1. `libdirectfb_nvt_uart_ir.so`: `nec_keycode_map` (52 NEC codes) → `custom_keycode_map` (DFB symbols);
  2. `/vendor/ice_keymapping_db.xml`: `KeyString` → **ICE keypress id** (512+);
     `/vendor/vk_keymapping_db.xml`: `KeyString` → DIAL/virtual-remote code (1000+);
  3. **the per-key codes come from the device profile**, not from any binary: `/conf/mb230_hwprofile.bin`
     (24,514 B, EFSL container; copy in `artifacts/protocol/mb230_hwprofile.bin`). This is why no static
     `{code, id}` table exists. The map is already recovered — `artifacts/reports/IR-KEYMAP-2026-10-30.md`
     + `artifacts/protocol/ir-keymap-2026-10-30.csv` (ICE id → KeyString → RC code, 143 rows), read out of
     the running process at `*0x77ae5c` (aurora is `ET_EXEC`), so no EFSL parsing is needed.
* **layout numbers** — the `.ui`/`.txt` packs carry the geometry the stock UI uses; replicate those
  values for parity instead of eyeballing screenshots.
